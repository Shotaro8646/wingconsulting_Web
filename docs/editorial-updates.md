# 記事とニュースの更新

業務の解説・分析・手順は `/blog/` の記事一覧、制度・技術の発表や適用日の変更は `/news/` のニュース一覧に載せる。
ニュースは公開日または最終更新日の新しい順に並べ、トップページのニュース欄にも反映する。記事一覧にニュースのカードを混ぜない。
関税の更新履歴は `/news/japan-tariff-impact`、購読用の配信は `/tariff-news.xml`。
旧URL `/blog/japan-tariff-impact` とその `.html` 付きURLは、301で新URLへ案内する。
毎日の確認で重要な変更が見つかった場合だけ公開する。日付だけを進めない。

- 施行・適用日、対象品目、原産地、例外、還付条件を公式発表で確認する。
- JETROなどの報道に依拠した情報は、その旨を本文に書く。直接確認していない資料を確認済みと書かない。
- 同じ話題は既存URLを改訂する。新記事は、独立した論点と十分な根拠がある場合に作る。
- 事実、編集部の分析、仮の計算を区別する。実績・削減率・顧客の声を裏付けなく書かない。
- 「重要です」「つなげる」だけで説明を終えず、誰が何を確認・比較するかを具体的に書く。「伴走」「一気通貫」などの定型句や、裏付けのない断言を避ける。
- 結論、対象条件、期限、数値の読み違いを防ぐ注意点は、本文中の短い句を `strong` で太字にする。見出しや項目名だけの強調にせず、段落全体を太字にもせず、太字だけを追っても要点が分かるか確認する。
- 著者はWing編集部。代表者の氏名・写真・個人の連絡先・本人を特定できる経歴を加えない。日付の経過だけでこの方針を解除しない。
- 本文の公開・更新日、JSON-LD、該当する一覧、トップの掲載欄、サイトマップ、llms.txt、関連リンクを合わせる。
- ニュース本文のJSON-LDは `NewsArticle` と `WebPage`、パンくずは「Wing → ニュース → 題名」。業務解説は `Article` を使い、記事一覧から案内する。
- 関税の実質的な更新はRSSに項目を追加する。同じ更新を毎回新着として配信しない。
- 置き場や見た目だけを変えた場合は、RSSの配信ID・配信日時や本文の公開日を変えない。
- 表示・内部リンク・出典・個人情報・差分を確認してから公開し、本番のURLを確認する。

## 表示と計測

新しい記事・ニュースは `assets/editorial.css` を共有し、本文はHTMLで配信する。
一覧を切り替えるリンクとニュースの行は `assets/content-navigation.css` を使う。両一覧はJavaScriptが無くても読める。
記事一覧、PFAS規制まとめ、chemSHERPA実務ガイドは、それぞれ `assets/` にある静的CSSを使う。
クラス名を変える場合は対応するCSSも更新する。Netlifyでのビルドは不要。

GA4は `assets/analytics.js` を通して本番ホストだけで計測する。
問い合わせリンクは `contact_click`、フォーム送信直後の完了画面への遷移は `generate_lead`。
受信内容が営業目的・スパムかどうかは、このイベントでは判定できない。問い合わせの質は別に確認する。
氏名・メール・相談内容などのフォーム入力値は計測コードに渡さない。
